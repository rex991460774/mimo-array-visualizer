1.0.1 是稳定性修复版本，修复了长时间运行（soak）测试中发现的两个问题。接口和数据格式没有变化，可以直接从 1.0.0 升级，项目库、分享链接和导入文件都保留。

## 修复

- **内存占用**：多人并发评估时，glibc 会为每个计算线程保留一块内存，而且空闲后不归还，常驻内存会涨到 2–3 GB。现在 Linux 下 `mimo-array-server` 启动时会自动设置 `MALLOC_ARENA_MAX=2`（如果环境里已经设置，就沿用已有的值），Docker 镜像和 systemd 示例中也写明了这个设置。同样 1200 次混合请求，常驻内存从 2159 MB 降到 466 MB，耗时不变。
- **导出文件占满磁盘**：以前导出的报告和图片要 24 小时后才清理，导出频繁时 `jobs/` 目录约每小时增长 100 MB。现在除了 24 小时期限，还限定最多保留最近 100 个、合计不超过 1 GB，超出时先删除最旧的，启动时也会清理上次运行留下的文件。
- **导出排队**：同时排队或执行中的导出最多 8 个，再提交会返回 429，界面提示“服务器正在处理其他导出任务，请稍后再试”，不再无限排队。

## 升级

- Docker：`git pull && docker compose up -d --build`（需要重建镜像）。
- wheel：`pip install` 下方附件的 wheel 地址，然后重启服务。
- 源码 / systemd：`git pull`，再运行 `scripts/setup_server.sh`，然后重启服务。如果想在 service 文件里明确写出内存设置，请重新复制 `deploy/mimo-array.service`。
